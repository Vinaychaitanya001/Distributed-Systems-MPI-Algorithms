# Q3: Bitonic Sort

## Compilation
To compile the program on the cluster, load the required MPI module and use the C++ MPI compiler with O3 optimizations:

```bash
module load hpcx-2.7.0/hpcx-ompi
mpicxx -O3 -o bitonic bitonic_sort.cpp
```

## Execution (For TA Grading)
The program now reads the input dataset from `input.txt` (generated by `generate_array.cpp`) and outputs the final sorted array to `output.txt`.
To automatically compile, generate the dataset, and run a single test case (e.g. for grading), submit the basic run script:
```bash
dos2unix submit_q3.sh
sbatch submit_q3.sh
```

## Benchmarking (For Report Analysis)
To automatically run the full benchmark suite across $N \in \{1024, 16384, 65536, 131072\}$ and $P \in \{1, 2, 4, 8\}$, submit the analysis script:
```bash
dos2unix analysis_q3.sh
sbatch analysis_q3.sh
```
The output will be saved to `bitonic_results.log`, containing the raw timing and speedup metrics needed for the report plots.

## Correctness Verification
The program automatically verifies its own correctness at runtime. The Master process (`rank 0`) creates a copy of the unsorted original array and sorts it using a pure sequential Bitonic Sort algorithm (`bitonicSortSeq`). It then strictly compares every element of the MPI-gathered array against the sequentially sorted array. It prints `Status: SUCCESS` if and only if the arrays match perfectly.

## Algorithm Constraints Handled
*   $N$ and $P$ are strictly checked to ensure they are cleanly divisible.
*   The code utilizes a custom, recursive `bitonicSortSeq` function instead of relying on `std::sort`, strictly fulfilling the algorithm's requirements.
*   Network exchanges use the required block-wise "compare position-wise and keep min/max" logic before sorting locally.
